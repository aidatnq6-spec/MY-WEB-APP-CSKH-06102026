## Project overview

This is a Next.js App Router application for an internal Vietnamese customer-support/technical-support script library (CSKH Script). It uses React 19, TypeScript, Tailwind CSS v4, shadcn/ui, Lucide icons, and Firebase Authentication/Firestore.

The main user flow is:

1. `/` redirects to `/login`.
2. `/login` authenticates with Firebase Email/Password or Google popup.
3. `/dashboard` listens to Firebase Auth state and redirects unauthenticated or disallowed users back to `/login`.
4. The dashboard provides support-script browsing by business category, search, issue selection, troubleshooting steps, escalation guidance, copy-to-clipboard, and JSON export.

Firebase browser configuration is read from `NEXT_PUBLIC_FIREBASE_*` variables. `.env.local` is ignored by Git; use `.env.example` as the variable checklist. Email allowlisting is optional and controlled by `NEXT_PUBLIC_ALLOWED_EMAIL`; when set, both email and Google sign-ins must match it.

## Commands

```powershell
npm run dev             # Start the Next.js development server
npm run build           # Create a production build
npm run start           # Serve the production build (run build first)
npx tsc --noEmit        # Type-check without emitting files
npm run lint            # Run the configured ESLint command
```

There is currently no test runner or test script configured in `package.json`. Do not assume Jest, Vitest, Playwright, or Cypress is available; use type-check/build and manual browser verification unless adding a test tool deliberately.

After changing `.env.local`, restart `npm run dev`; Next.js loads public environment variables at process startup.

## Architecture

- `app/layout.tsx` is the root layout. It supplies Vietnamese document metadata, Geist fonts, global CSS, and the shadcn `TooltipProvider`.
- `app/page.tsx` only redirects `/` to `/login`.
- `app/login/page.tsx` is the branded login screen. `components/login-form.tsx` is a client component containing Firebase Email/Password and Google popup flows, Firebase persistence selection, allowlist checks, loading states, and localized errors.
- `app/dashboard/page.tsx` is the main client dashboard. It wraps the page in the shadcn `SidebarProvider`, renders `AppSidebar`, protects the route using `onAuthStateChanged`, and owns the current category/search/selection UI. The dashboard currently contains the script list/detail experience and metric cards; several header/sidebar actions are visual placeholders until their dialogs are implemented.
- `components/app-sidebar.tsx` supplies the sidebar-07 navigation (team switcher, collapsible navigation groups, projects, user menu). `components/ui/` contains generated shadcn primitives; prefer composing these components over introducing custom equivalents.
- `lib/categories.ts` defines the five business categories (`cks`, `hddt`, `bhxh`, `canho`, `dautu`), their icons, colors, and labels. `lib/types.ts` defines `Issue`, priorities, backups, and serialized app state.
- `lib/use-app-data.ts` owns client-side issue state. It seeds the current issue catalog, reads/writes localStorage (`cskh-script-data-v1`), tracks checklist/view-related state, and exposes filtering/selection helpers. Changes to the issue model or persistence should be coordinated here and in `lib/types.ts`.
- `lib/firebase.ts` is the Firebase client adapter. It initializes the browser app once, exports Auth/Firestore/Google provider instances, sets local/session persistence, translates auth errors, and applies the optional email allowlist. Keep Firebase-only APIs in client components or client-safe modules.
- `app/globals.css` contains Tailwind v4, shadcn theme variables, sidebar tokens, and dark-mode variables. Use the existing semantic tokens (`bg-background`, `text-muted-foreground`, `border-border`, etc.) when styling new UI.
- `components/ui/` is generated by shadcn CLI. If adding UI primitives, use `npx shadcn@latest add <component>` and preserve the existing import alias/configuration.

## Data and authentication notes

- The Firebase client config is intentionally exposed through `NEXT_PUBLIC_*` variables because it is a browser Firebase app config; authentication and Firestore rules remain the security boundary.
- Enable **Email/Password** and **Google** under Firebase Console → Authentication → Sign-in method. Add local/production domains to Firebase Authorized domains.
- The dashboard currently stores issue data locally through `useAppData`; Firestore initialization exists but cloud issue-state synchronization is not yet wired into the dashboard.
- The seed catalog currently covers the CKS, HĐĐT, and BHXH categories. Căn hộ and Đầu tư categories exist in the UI but may have no seeded issues yet.
- Keep user-facing strings in Vietnamese and use Lucide/shadcn patterns consistent with the existing dashboard.
